# Deployment

## Steps

### D-S01: 分阶段迁移设备身份

先发布兼容旧 connector 的 Relay 与数据迁移，再发布简化后的 connector 和添加设备界面；在淘汰旧参数前确认活跃设备已完成绑定且无歧义数据。

### D-S02: 验证生产连接生命周期

在真实部署中验证首次连接、重叠连接拒绝、正常重连、租约超时和撤销，并确认 dashboard 与会话操作始终指向同一设备。

## Acceptance criteria

### D-AC01: 既有设备无身份断裂

部署记录与生产抽查证明既有设备、session 和事件在迁移前后保持相同归属，无法自动迁移的歧义项在发布前被明确列出并处理。

### D-AC02: 单连接策略在 Relay 生效

外部验证证明同一 token 的第二条并发连接收到稳定错误且第一条连接可继续执行命令；第一条连接结束或租约过期后，新连接能够成功接管。

### D-AC03: 新设备无需客户端身份参数

从生产 dashboard 添加一个设备后，仅使用 Relay 地址与一次性 token 即可启动 connector，并看到服务端名称、在线状态及其 session。
