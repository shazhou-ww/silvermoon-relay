# 以设备身份约束连接 token

## 问题

用户创建连接 token 时已经为设备命名，但 connector 仍需自行提供 ID 和显示名；同一 token 还能以不同 connector ID 建立多个连接，造成设备身份重复且权限边界不清。

## 结果

“添加设备”在服务端创建稳定设备身份及其一次性连接凭据。connector 首次配置后从用户级 profile 读取连接信息，服务端决定设备 ID 与名称，并保证一个 token 同时最多对应一个活跃连接。

## 边界

- 服务端约束的是凭据连接数，不能证明 token 只存在于一台物理机器。
- 重叠的第二个连接不得打断既有连接；正常断线或租约失效后允许重连。
- token 默认存入系统凭据库；普通配置只保存 Relay 地址与凭据引用。无凭据库的 headless 环境可显式使用权限受限的 token 文件。
- 本 idea 不实现升级期间的 successor-token 无缝轮换，但设备与凭据模型须允许以后增加该流程而不改变设备身份。

## 验收标准

- 用户只需命名并添加设备，完成一次安全的用户级配置；后续启动无需重复输入 token、设备 ID 或名称。
- 同一 token 无法同时维持第二条连接，且被拒绝的连接不会影响现有设备会话。
- 重连、撤销和未来凭据轮换均保持稳定设备归属及历史连续性。
