# 借鉴 VS Code 重构 Agent 消息流渲染

## 问题

Relay 当前把 Agent Host 的回合内容压平成 message、tool、status、error 等独立事件，Web 端再分别渲染文本和原始数据卡片。响应片段的先后关系、工具生命周期和增量状态因此难以表达，也无法复用 VS Code 已验证的 Agent 消息流阅读体验。

## 结果

固定一个 VS Code 开源代码 revision，追踪其从会话模型到消息组件的渲染链路，提炼可复用的分组、状态与渐进披露策略并适配到 Relay。用户最终能按完整回合阅读 Markdown、工具进度、结果和错误，同时保留实时更新与历史重放的一致顺序。

## 边界

- 先核对确切源码、版本与许可证边界；借鉴策略和信息结构，不直接复制 VS Code 代码、资源或未验证的内部行为。
- 只在渲染所需范围内调整协议与 Connector 映射，并为现有事件消费者保留明确的兼容路径；不改变 Session、Device 或账户领域关系。
- [UI 变更评审](./ui-review/index.html)中的 After 是待源码追踪验证的方向草案，不是已确定的 VS Code 行为或最终视觉规范。

## 验收标准

- 可复现的源码映射记录确切 VS Code commit、相关文件与符号，并说明 Relay 当前链路和参考链路的对应关系。
- 用户消息、Assistant Markdown、工具开始与完成、错误、系统通知和运行状态在代表性会话中保持原始语义、顺序及增量更新，历史重放不重复或错位。
- 桌面与窄屏均能清晰区分回合和活动层级；受支持的事件无需依赖原始 JSON 才能理解，键盘与辅助技术可访问关键状态。
