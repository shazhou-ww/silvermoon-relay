# Implementation

## Steps

### I-S01: 建立消息流滚动状态

使用独立的 `TranscriptScroll` 消息容器，按 Device + Session 的组合身份重建滚动状态；历史数据同样按组合身份隔离，避免切换时渲染旧消息。首次历史布局后定位到底部，以距底部不超过 64 CSS px 判定自动跟随。监听内容及视口尺寸变化，兼顾流式快照、延迟媒体、输入框增高和移动端隐藏/恢复，并防止布局产生的旧滚动事件覆盖用户的跟随意图。历史同步请求与增量轮询分离，连接状态变化不再清空消息。

### I-S02: 增加返回最新消息控件

在消息区与输入区之间保留固定的 4rem 控件区域，以浮动样式显示 `Jump to latest`，不覆盖消息或输入区，也不因按钮显隐改变消息视口高度。仅在离开底部阈值后显示；激活后立即隐藏并把焦点移交给可键盘滚动的消息区，按系统动态效果偏好平滑或即时定位。用户滚轮、触摸或滚动键可中断尚未完成的返回动画。界面文案保持现有英文风格。

### I-S03: 覆盖滚动交互回归

新增以真实 Chromium 和模拟 relay API 驱动的 Playwright 回归，并接入现有 CI 的 check job；覆盖桌面、移动端和 320px 窄屏。测试与截图证据见 [实施验证](./Implementation-Evidence.md)，复现命令见仓库 README。

## Acceptance criteria

### I-AC01: 最新内容定位可靠

浏览器断言距底部不超过 1 CSS px：长 Session 首次加载、延迟历史返回及跨 Device 同名 Session 切换后均定位到底部；距底部 64px 时追加事件恢复到底部，65px 时显示返回控件。流式内容及延迟媒体尺寸变化同样遵守跟随状态。

### I-AC02: 历史阅读不被打断

浏览器记录并比较阅读位置，证明用户离开底部后，追加事件、空轮询、工具消息筛选、连接断开/恢复、流式快照及底部媒体尺寸变化不会主动拉回最新位置；移动端在会话列表与原 Session 之间导航时保留阅读位置。内容移除导致的浏览器锚定或必要范围裁剪不承诺保持相同数值 scrollTop。

### I-AC03: 返回控件可访问且响应式

三个视口的浏览器检查及截图证明：浮动控件仅在需要时出现，具有明确名称、关联消息区及至少 44px 的高度，处于消息视口之外且在输入区之上；指针和 Tab/Enter 均可激活，激活后隐藏并保留有效焦点，减少动态效果模式立即返回底部。
